**F3 — Major: the link-graph guard's coverage guarantee does not hold as claimed, and the evidence asserts a failure mode the code cannot produce.**
- `cmake/TargetGraph.cmake` (`gufo_write_link_graph`) writes every protected name that is not a live CMake target into the report's `absent` array; `tools/ci/check-target-graph.py` then computes `declared = report["targets"] ∪ report["absent"]`, so a protected target that **stops existing** (renamed or dropped from a CMakeLists) is accepted as "coverage". The guard then silently stops checking that library, and its replacement is only checked if it happens to declare a `library.json`.
- `negative-proofs.txt` states "A target that disappears from the report entirely also fails, so the guard cannot be silenced by an unlisted library", and `target-ownership.md` says "an unregistered library cannot slip through". Both are not what the code does; the only catch is a name the *checker's* own list has and the generator omits entirely (e.g. removal from `GUFO_LINK_GRAPH_PROTECTED`).
- The new unit fixture `tests/tools/check_target_graph_test.py::test_missing_protected_target_fails` hides this by building a report **without** the `absent` key, which the real generator always writes; `test_absent_target_covers_a_configuration_that_skips_it` then enshrines the loophole.
- Two further holes in the same walker: `forbidden` is read from the report rather than asserted (`forbidden: []` would pass silently), and `gufo_link_graph_entry` drops any `INTERFACE_LINK_LIBRARIES` item that is not a plain target or a `$<LINK_ONLY:…>`/`$<BUILD_INTERFACE:…>` wrapper — a config- or genex-wrapped edge (e.g. `$<$<CONFIG:Debug>:gufo_serving>`, `$<TARGET_PROPERTY:…>`) is invisible.
- Smallest fix: have `gufo_write_link_graph()` also write the configuration (`"hip": true/false`) and have the checker (a) hardcode the forbidden set `{gufo_serving, gufo_http}` and fail if the report's list differs, (b) accept `absent` only for a named HIP-tier allow-list (`gufo_hip_host`, `gufo_cache_hip`) and only when the report says HIP is off, (c) fail on any interface item it could not classify instead of skipping it. Then correct `negative-proofs.txt` and `target-ownership.md` to the mechanism that is actually proven.
- Verify: `python3 tests/tools/check_target_graph_test.py`; inject a rename once (`gufo_cache_hip` → `gufo_cache_hip2` in `CMakeLists.txt`), reconfigure, and show whether `extension_link_graph_gate` fails — retain both outputs; `python3 tools/ci/check-target-graph.py --report build/card09-gpu/gufo-link-graph.json --root . --show`.
