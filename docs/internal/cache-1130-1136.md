# Cache frontier and retention qualification

The cache series retains exact executed turn ends, delays preferential removal
of recent covered turns, preserves durable fallbacks under RAM pressure, and
uses prefix relations in disk eviction. The cost model remains diagnostic;
the cost-per-byte experiment is rejected.

## Cost-per-byte experiment

The replay uses the token arrays pinned at
`a32fc43bcb9ec66264f166b5162d93a9223557d5`, exported with
`tests/cache/retention_trace.py`. `cache_retention_replay` records each request's
cached/prefilled tokens and estimated interval cost as well as retention events.
It counts distinct serving turns and passes actual reuse into admission.
These historical prompt-only replays do not model generated-frontier placement,
disk I/O, numerical quality or wall time. They are not throughput measurements.

The [experimental patch](cache-1130-1136/retention-gds.patch) keeps pressure tiers,
uses the deepest retained fallback and unique payload bytes, advances a
GreedyDual watermark on pressure eviction, and updates admission/reuse stamps.
Fallback and sharing costs are recomputed during selection. Its stamp map is
outside the ledger, deliberately giving the experiment optimistic bookkeeping
cost. It is compiled separately; production has no ranking switch.

## Functional qualification

The same host directory retains production main/candidate binaries' evidence,
request reports, server traces, failures and follow-ups. Main is `580d053b`,
using the pinned Nix GCC 16.2 / ROCm 10.1 toolchain and lock-mode extension set.

The first Flash-Next AR candidate exposed pending generated writes displacing
prompt anchors, and the disk-spacing checker treating demotions as ordinary
spaced captures. Queue overflow now drops optional generated writes before
prompt anchors. Publications explicitly identify spacing exemptions, while the
checker still rejects too-close ordinary prompt captures.

Under high-throughput speculative decoding (DFlash2 at 80 tps), rapid completion
of multi-turn requests revealed that `Extends` and `Below` evaluated across turns
with differing prompt identity spans (`input`), preventing write-queue coalescing
of older generated frontiers across turns. Furthermore, unconstrained optional
write-through jobs could pin up to 100% of the cache RAM budget, causing
foreground capture starvation. `Extends` and `Below` now match conversation
descendants sharing either `input` or `lineage`, and `PersistenceQueue::TrySubmit`
bounds optional generated writes to half of the queue's pinned byte budget
(`max_bytes / 2`), leaving ample headroom for foreground prompt captures.

All four production release profiles completed the 11 functional suites on
`gfx1151`. These runs pass functional assertions in the Python harness;
the release binaries have C++ assertions disabled. This is functional evidence,
not a timing qualification:

The 2 GiB standalone interleaved thinking/tool frontier fixture

comparison commands. Strict comparisons also contain timing flags and some cancellation-history

remain unqualified pending matched affected-history controls.

## Code review and verification

Three context-free subagent reviews examined the patch against `580d053b`.
The first found that disk eviction needed temporary ledger headroom; eviction
now uses prepaid record storage, with a full-ledger regression test. The second
found synchronous access-history writes under the serving lock; lookup only
marks dirty history now, with explicit quiescent flushing and shutdown flush.
An abrupt shutdown can lose advisory recency updates, without losing checkpoint
durability. The third review found no substantive issues. It did not execute
tests.

Follow-up admission rules keep unused generated copies below prompt retries,
including at record-table capacity. Optional generated admission cannot evict
normal prompts or previously used frontiers. Foreground pressure can discard
queued unused frontier writes, release their pins and complete cancellation
callbacks; active I/O is never cancelled. Generated-job coalescing also obeys
the half-budget limit. Dedicated tests cover these contracts, callback/drain
ordering and eviction at full ledger capacity.

The resumed candidate passed functional checks across Flash AR/MTP and Qwen
AR/DFlash2. Evidence, including superseded attempts and strict comparison
failures, is retained under
`/home/mixer/gufo-qualification/cache-1183-resume-20261112/`.
Flash AR's broad retry losses were removed; the final three-profile run still
shows cancellation-history prefill differences in Flash MTP and Qwen DFlash2.
These results do not establish a performance pass.

The CPU `check-pr` gate passes all 117 tests. The extension API checker reports
0.3.6 and 133 surface paths, including the additive pending-write discard API.
The Windows non-interactive extension CLI fixture uses an empty pipe because
the Windows CRT treats the NUL device as a terminal. Windows package, extension
contracts, model checks and repository CI passed for `139213a5`.

## Completion follow-up

Idle generated capture runs in a bounded cache-owned task, with slot exclusivity
and an admission barrier. Concurrent active leases keep synchronous capture;
new admission and teardown wait for the idle task. Optional task setup and
capture failures preserve the completed live execution. Tests cover blocked
background work, admission waiting and setup refusal. Cancellation during an
active copy is observed after that bounded copy completes.

Disk reuse protection lasts one configured disk budget of newly admitted
unique payload bytes, including reuse inherited from descendants. Checksummed
40-byte use records preserve the byte clock and reuse coordinate across clean
restart; legacy 16-byte recency records remain readable. Advancing the clock
marks every surviving history dirty, so retiring newer admissions cannot revive
expired protection after restart. Tests cover reuse expiry and restart.

Three additional context-free reviews covered this follow-up. They found a
thread-handle publication race, stale persisted turnover clocks and optional
setup failure invalidating live execution. All were fixed; the last review
found no substantive issues. The focused serving, tiered and disk tests pass.
GPU continuation guards pass for Flash AR/MTP and Qwen's leased, batch and
scalar mutation paths. The guard binaries have C++ assertions enabled.

Completion evidence lives under

The [completion report](https://github.com/gufo-org/gufo/pull/1183#issuecomment-6827774423)
records final per-profile functional/pressure outcomes, Pi tool and compaction

All failed attempts remain beside successful results. Historical GDS evidence

The constrained compaction follow-up exposed a shared grid fallback preceding
its actual token divergence. Fork detection now uses retained prefix relations,
including history records; short retry replacement cannot bypass that protection.
The existing branch contracts and a new delayed-divergence regression pass.
A context-free review found no substantive issues in this correction. The full
CPU gate passed 117 tests in 99.19 seconds before this focused correction.

Flash AR's edit, near-limit compaction and pressure histories pass under 2 GiB
in `qualified-pressure-flash-ar`. Its repeated cancellation retry still added

frontiers now leave projected headroom for another equivalent incremental
capture where the backing provider exposes capacity checks. Refusal cannot
bypass that limit through disk staging. A two-private-block serving regression
covers RAM-only and disk-enabled configurations. The fresh review found only
nits; this is a projected capacity check, not a reservation for arbitrary prompts.

## Final qualification

The branch was rebased on `e671f85e`. Main itself then failed the Flash-Next
`thinking-tool-cancel` history: an identical retry produced different seeded
output. Bisection identified #1158 (live-frontier alignment of replayed
answers). Alignment ran when the HTTP request arrived, before a cancelled
stream had committed its frontier, and an unchanged retry of an aligned prompt
was tokenized afresh. Alignment now runs at scheduler admission, never
rewrites a prompt whose own tokens begin a frontier, and rewrites an unchanged
retry to a retained checkpoint of the aligned prompt, mapping the stable
boundary across trimmed reply whitespace. CPU regressions cover each rule.

The matched control is `e671f85e` plus those serving fixes, so comparisons
isolate the retention series. Both use the pinned Nix toolchain and lock-mode
release builds on `gfx1151`. Each control passed `long-context` and `cache`.
The candidate passed all 11 suites in Flash-Next AR/MTP and Qwen27B AR/DFlash2.

| Profile | Functional | Work changes against control |
| --- | --- | --- |
| Flash-Next AR | 11/11 | Two disk restores reuse 11 and 20 more tokens |
| Flash-Next MTP | 11/11 | None |
| Qwen27B AR | 11/11 | Three disk restores reuse 9, 18 and 12 more tokens |
| Qwen27B DFlash2 | 11/11 | Two disk restores reuse 9 and 12 more tokens; one later sampled output differs |

No request prefilled more tokens than the control. The Qwen27B AR
cancellation restore reads a deeper generated frontier from disk (99 ms rather
than 3.8 ms from RAM) and prefills 12 fewer tokens. Its TTFT is 414 ms rather
than 402 ms, which stays within the 5% margin. The DFlash2 output difference
follows a restore from a generated frontier instead of prefilled tokens. The
suite's own replay assertions pass.

The first matrix run flagged several timings as inconclusive. Disk restores
with identical bytes moved both faster and slower, by up to about 25%. Alternating
control/candidate `long-context` reruns did not reproduce the Flash-Next
cold decode or Qwen27B cold snapshot flags; three of the four candidate runs
qualified, and the fourth flagged only server startup. Disk-restore timing
remains inconclusive, not a qualified pass. The CPU `pr` gate passes 119
tests. Evidence lives under `/home/anvil/gufo-qualification/pr1183-20261112/`
on the qualification host.
