# DeepSeek V4 Flash experiments

| Experiment | Decision / evidence |
| --- | --- |
| Explicit IQ2/Q8 rounding, HC/router and attention/indexer arithmetic | Retained for ROCm 10.1; original 4K/12K narrow-prefill limits pass, 7.2.3 reference vectors remain exact, and C1/C2 sparse-boundary replay passes. [Migration checks](ROCM.md). |
| Bounded compressor stores for resumed prefill | Retained locally: group only up to the next pool/shift boundary, preserving per-row counts and speculative rollback. Exact operator state/output checks pass on 7.2.3/10.1; 16K HTTP prefill improves about 5–6%. |
| C1 vocabulary head cap and device-side Markov chain | Retained locally: preserve the complete support transformer and exact sequential choices, skip unused vocabulary rows and read the completed chain once. FP64 oracle, scalar replay, bounds and end-to-end token/draft counts pass. |
| Reuse packed IQ2 weights across short token tiles | Retained locally: exact integer sums and final FMA; rotating-weight operator probes improve 6–15%, with smaller request-level gains. Exact operator checks pass on 7.2.3 and 10.1; focused final HTTP controls retain text and draft counts. |
| Prefetch attention values in groups of 16 | Retained locally: same row-by-row FMA; 49 exact GPU/independent FP64 cases pass on 10.1. With restored recent-cost backoff, d0 generation improves 21.55→22.18 tok/s and the first 16K continuation 19.52→20.13; the old 24.18 trajectory remains faster. |
| Two-launch single-token decode attention | Retained locally (2026-10-28): one kernel scores 32-row tiles for 16 heads with coalesced LDS-staged rows, and a second replays each head's 256-thread softmax and accumulates 16 heads x 128 dimensions per workgroup. Every dot product, reduction tree, and value FMA chain is unchanged. 1,069 bitwise harness cases pass, including finite mask values of several magnitudes, and so do the 49 exact and FP64 cases. Bit-identity holds for ROCm 10.1 and Clang 24 codegen. The dot-sum order `(s0+s2)+(s1+s3)` and the separate mask add come from the old kernel's compiled ISA, so a compiler change needs the harness rerun. The launchers require `head_dim` 512 and return false otherwise. On the 860M, launches are 2.7-6.4x faster at 64 heads and 1.7-3.1x with 13 heads, about gfx1151's workgroups per CU. On gfx1151, tg64 improves 15.88→16.60 tok/s at 32K and 15.59→16.38 at 64K. At d0 it is unchanged. |
| Recent completed-token-cost backoff | Restored: the earlier configuration reached 19.52 tok/s on the corrected continuation with identical text. The final combination passes both builds and 142 functional requests, and reaches 20.13 tok/s. Cache/admission timing flags remain inconclusive. |
| Later confidence/width policy trials | Discarded; only the previously tested recent-cost backoff is restored. |
| Coarse DSpark allocation and asynchronous tensor copies | Rejected: no measurable complete-request improvement. |
| Smaller Q8 launch groups on ROCm 10.1 | Rejected: rotating 16 weight matrices preserves exact outputs, but most gains are only 0–3%; four-row groups slow the 8192-wide scalar/HC kernels by 8–10%. Existing loads already compile to vector memory operations. |
| Read small F16 decode GEMV inputs directly | Retained locally (2026-10-28): the warp-row kernels read `x` from global memory at 16 rows per block instead of staging it in LDS, and the one-token ordered kernel issues 16 groups of loads before their FMAs. FMA order is unchanged, and 3.5M outputs are bit-identical. Small shapes are 1.11–1.45x faster, and `indexer_q` and `scaled_single_1640` are 3–5% slower. On gfx1151, tg64 improves 17.85→18.12 tok/s at d0, 15.71→15.88 at 32K and 15.42→15.59 at 64K. |
| Pad the rows of the F16 compressor, indexer, and HC mix weights | Retained locally (2026-11-05): gfx1151 reads 8 KiB F16 rows at about 103 GB/s with a power-of-two row stride and at about 203 GB/s with 512 B of padding per row. The loader uploads these weights with 256 halves of padding per row, which adds 122 MiB of device memory, and every F16 GEMV and hipBLASLt route takes the row stride. Outputs of every padded route are bit-identical to the packed rows. The ratio-4 compressor pair is 1.97x faster, the ratio-128 pair 1.71x, the indexer pair 1.75x, and `indexer_q` 1.26x. On gfx1151, the padding improves tg64 17.59→18.66 tok/s at 32K, 16.84→17.87 at 128K, and 16.70→17.70 at 160K. A 4,096-token prefill at 131K is unchanged. |
| Exact partial top-k | Retained through 65,536 compressed keys; exact ties and bounded fallback. |
| One-workgroup indexer top-k up to 65,536 keys | Retained locally (2026-11-05): above 32,768 keys, which a context passes at 131,072 tokens, the selection fell back to a chunked merge tree. A 1,024-thread instance of the exact partial selection covers 65,536 keys, every instance keeps its input keys in registers (0 B scratch), and rows of at most eight decode tokens run 512 threads up to 16,384 keys. One decode row takes 52.6–59.5 µs instead of 107.5 µs at 32,769–49,152 keys, and 25.0 µs instead of 34.6 µs at 8,190 keys. A 1,024-row prefill selection at 47,104 keys takes 3.4 ms instead of 19.3 ms. 240 kernel checks are bit-identical to the old dispatch and a CPU ordering. On gfx1151, tg64 improves 17.28→17.38 tok/s at 32K, 16.24→16.53 at 128K, and 16.11→16.38 at 160K. |
| Seed the indexer top-k from a 12-bit key histogram | Retained locally (2026-11-05): a histogram pass over 4,096-key blocks counts the top 12 bits of each ordered score, and the selection workgroup starts from the boundary bin instead of narrowing from the top digit. Decode rows above 9,216 keys and batches above 32,768 keys use it. One decode row at 32,769–65,536 keys takes 36.3–43.4 µs instead of 52–71 µs unseeded, and four rows at 47,104 keys take 38.3 µs instead of 176.9 µs. A 4,096-row prefill chunk needs 64 MiB of temporary histogram memory. On gfx1151, tg64 improves 16.53→16.66 tok/s at 128K and 16.38→16.51 at 160K. At 32K, decode rows stay below 9,216 keys, and tg64 is unchanged. |
| Indexer query packing and shared scratch | Retained; unchanged F16 bytes, scores and full-logit controls through 64K; no persistent KV precision change. |
| Score 32 indexer keys per C1 decode block | Retained locally (2026-10-28): one block per compressed key reloaded the 32 KiB query. Each block now scores 32 keys, and each wave keeps 16 query heads in registers. The `permlanex16` and DPP butterfly adds the same partials as the old shuffle-down tree, and 27.3M scores over 378 cases are bit-identical. On gfx1151, tg64 improves 14.95→15.47 tok/s at 32K and 14.17→15.18 at 64K. At d0 it is unchanged. |
| FP4 mirror of the indexer keys for decode scoring | Rejected (2026-11-05): an exact 68-byte FP4 code and block-exponent mirror of each F32 key row cuts the bytes the scorer reads, but the scorer is not limited by memory bandwidth. It is 1.07x faster at 32,768 keys for one token and 0.97–0.99x at three and eight tokens, and each decode row adds 0.25 µs of mirror writes. |
| Batched speculative projections/attention | Retained; private session state and scalar-equivalent replay. |
| Projection/mHC fusion | Retained only where independent HC/Sinkhorn and model guards pass. |
| Spread the decode HC split norm over 16 blocks per row | Retained locally (2026-11-05): one 256-thread block per row computed the Sinkhorn split, the weighted sum, the RMS norm, and its Q8 forms. With 16 blocks per row, each block repeats the split and the sum-of-squares tree and normalizes 256 columns, and the residual loads start before the split. An AMD GPU operation on two NaNs returns the NaN in a fixed operand slot, so `v_mul_f32` and `v_fmac_f32` inline assembly keeps the operands of each product in the source order. 812 checks, including NaN residuals and weights, are bit-identical. The 86 launches of a decode token take 495 µs instead of 1,200 µs. On gfx1151, tg64 improves 18.66→19.01 tok/s at 32K, 17.87→18.17 at 128K, and 17.70→18.00 at 160K. |
| Fold the decode HC row norm into the HC mix projection | Retained locally (2026-11-07): a plain RMS norm launch wrote the normalized 16,384-wide HC row before each HC mix projection, 87 times per decode token. Each of the 24 mix blocks, or 4 for the output head, now repeats the norm's sum of squares, LDS tree, and reciprocal square root, and scales the row as it reads it, so no launch writes the normalized row. `v_add_f32` inline assembly keeps the operand order of the lane total. 460 kernel checks over 1.34 GB are bit-identical. The norm, mix, and split launches of a decode token take 1,527 µs instead of 1,748 µs. On gfx1151, tg64 improves 19.00→19.09 tok/s at 32K, 18.15→18.24 at 128K, and 17.98→18.06 at 160K. |
| Run the decode HC split in the HC mix launch | Rejected (2026-11-07): in one 40-block launch, the first 24 blocks to take a ticket compute the mix rows, and the last 16 wait on a release/acquire counter and run the split. It removes 86 more launches per decode token and improves tg64 0.2% more than the folded norm alone. Its split compiles the sigmoid underflow guard to vector instead of scalar instructions, and its outputs are not bit-identical: 35.2M kernel outputs and 11 of 56 whole-model comparisons differ. |
| Spread the Q8 HC-expand epilogue over four lanes | Retained locally (2026-11-07): after the warp sum of each output row, lane 0 computed all four HC streams in 21 dependent rounds of loads. Lanes 0–3 now compute one stream each and load their residual, post, and comb values before the projection loop, and each lane loads a Q8 block's codes in one clause. `v_add_f32`, `v_mul_f32`, and `v_fmac_f32` inline assembly keeps the old kernel's operand slots. Every candidate kernel and launch shape is bit-identical to the old kernel, and four seeded reorder and bit-flip controls fail. `attn_output_b` takes 165.4 µs instead of 181.3 µs per launch, 215.5 GB/s against about 224 GB/s for a read-only stream of its weights, and `ffn_down_shexp` takes 42.8 µs instead of 52.6 µs. On gfx1151, tg64 improves 19.09→19.60 tok/s at 32K, 18.24→18.73 at 128K, and 18.06→18.52 at 160K. |
| Pick greedy decode tokens on the GPU | Rejected (2026-11-08): an argmax over integer-ordered logit keys on the GPU, with the logits downloaded only when read, picks the same 71 tokens as the host, but tg64 improves only 0.03–0.12%, inside the run-to-run spread. It adds a kernel and a deferred logits path. |
| Compressed KV and use-sized scratch | Retained; capacity does not allocate a filled context. |
| Extra F16 HC rounding | Rejected: fails official formula oracle and worsens probability comparisons. |
| FP32 compressor/router | Rejected: local arithmetic improvements fail end-to-end continuation/trajectory controls. |
| One thread per expert for router probabilities of up to four rows | Retained locally (2026-11-05): eight waves share the FP64 probability work of a decode row instead of one, and one wave per row then selects. The 43 router launches of a decode token take 346 µs instead of 877 µs, and batches of two to four rows are 1.12–1.64x faster. From five rows the one-wave kernel is faster and stays. 900 checks and a sweep of all 2^32 F32 logits are bit-identical. On gfx1151, tg64 improves 17.38→17.59 tok/s at 32K, 16.66→16.84 at 128K, and 16.51→16.70 at 160K. |
| Paired IQ2 gate/up | Rejected (2026-09-19): exact forms slower; smaller tiles spill and fail exactness. |
| Overlap IQ2 gate/up block loads with decode in the C1 routed-expert kernel | Retained locally (2026-10-28): each lane loads the next step's gate and up blocks while it decodes the current one. The kernel stages Q8_K activations in LDS with a 272-byte block stride, and `__launch_bounds__(256, 10)` keeps all 96 decode workgroups resident on 20 WGPs. The kernel pins the scale product, the FMA order, and an opaque zero, and 19.4M outputs at 1–8 tokens match the old kernel bit for bit. On gfx1151, tg64 improves 17.54→17.85 tok/s at d0, 15.47→15.71 at 32K and 15.18→15.42 at 64K. |
| IQ2 gate/up sign-mask table and branch-free prefetch | Rejected (2026-11-05): a sign-mask table is 0.95x. Branch-free loads two steps ahead are 1.026x on the kernel, about 0.15 ms of a decode token, and double its code size to 60.7 KB. The kernel runs at 1.26x the time of a read-only stream of its weights, so little decode latency is left to hide. |
| Transposed sparse values | Rejected (2026-09-19): no retained end-to-end gain. |
| Constant pair indices in the 8-row IQ2 gate/up tiles | Retained (2026-10-08): runtime indices kept 144–176 B of per-thread arrays in scratch with clang 22 and 23. The explicit scale product and FMA keep every output bit-identical to the scalar LUT kernel; the tile kernel is 9–10% faster and pp8–pp24 1.7–2.0% faster in isolated PR measurements. |
| Launch bound for the register-cached plain RMS norm | Retained (2026-10-08): the default 1,024-thread bound limited it to 192 VGPRs, and clang 23 spilled one; bit-identical. |
| Fold C1 decode quantize, RoPE and KV-store launches into their producers | Retained locally (2026-10-28): at depth a token launches 1,205 kernels instead of 1,720, or 1,930 when ratio-4 compressors emit. Each launch costs about 1.6–2 µs of GPU gap on gfx1151. Every cache byte, intermediate, and logit is bit-identical over 43-layer synthetic-weight decodes at seven depths. Two variants changed bits and were replaced, a strided RoPE pair loop and a Q8_0 code computed from the rounded scale. On gfx1151, tg64 improves 18.10→18.48 tok/s at d0, 16.60→16.94 at 32K and 16.38→16.71 at 64K. |
| Pool the whole compressor windows of unaligned resumed chunks together | Retained locally (2026-10-28): only the rows before the first window boundary and after the last keep the per-span store and update launches, so a 977-token append at depth 30,001 launches 2,714 kernels instead of 64,298. Logits, final HC rows, every raw, compressed and indexer cache byte and every compressor state are bit-identical over 18 synthetic-weight resumed prefills, including ragged heads and tails, ratio-128 windows and 4,096-row chunk crossings. On the 860M the two compressor stages of that append fall from about 440 ms to 300 ms. On gfx1151, that append prefills at 390.8 tok/s instead of 369.0, the same speed as an aligned 976-token append, and appends of 130 and 4,100 tokens improve 3.0% and 5.8%. |
